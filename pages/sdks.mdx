# SDKs

Lariba Cloud publishes a public JavaScript/TypeScript SDK repository for developer integration work.

The SDK is currently a **developer-preview integration surface**. Its package mechanics are valid and buildable, but its event-ingestion request contract is not yet aligned with the canonical public ingestion contract documented by Lariba Cloud.

For production ingestion, use the documented HTTP API until that compatibility gap is closed.

## Current availability

| SDK | Status | Recommended use |
| --- | --- | --- |
| JavaScript / TypeScript | Developer preview | Evaluation and controlled integration work |
| Python | Not currently available | Use the HTTP API |
| Other languages | Not currently available | Use the HTTP API |

## JavaScript / TypeScript package

The public repository is:

- [node63labs/lariba-sdk-js](https://github.com/node63labs/lariba-sdk-js)

Current package metadata identifies:

```text
name: lariba-sdk
version: 1.0.0
license: ISC
Node.js: >=18
```

The package exports CommonJS, ESM, and TypeScript declaration outputs and is installed directly from GitHub:

```bash
npm install github:node63labs/lariba-sdk-js
```

The current package name is unscoped:

```text
lariba-sdk
```

Do not assume that a scoped registry package such as `@laribacloud/lariba-sdk-js` is published unless a future release explicitly documents that distribution channel.

## Current client API

The current SDK exports:

```ts
export class Lariba
```

Its constructor accepts positional arguments:

```ts
new Lariba(apiKey, baseUrl?)
```

Example reflecting the current SDK source:

```ts
import { Lariba } from "lariba-sdk"

const apiKey = process.env.LARIBA_API_KEY
const baseUrl = process.env.LARIBA_API_BASE_URL

if (!apiKey || !baseUrl) {
  throw new Error("Lariba Cloud API configuration is required")
}

const lariba = new Lariba(apiKey, baseUrl)

await lariba.track("user.signup", {
  plan: "starter"
})
```

## Compatibility boundary

The current SDK implementation sends events to:

```text
POST /v1/events
```

with an SDK-specific body containing `event`, `properties`, and `timestamp`.

The canonical public event-ingestion documentation uses:

```text
POST /v1/events/ingest
```

with the documented ingestion fields including `event_type` and `source`.

Because these contracts differ, the SDK must not be treated as the authoritative production ingestion contract yet.

Until the SDK and public API contract are synchronized:

1. use the HTTP API for production event ingestion;
2. treat the SDK as developer preview;
3. validate compatibility before adopting an SDK release;
4. use the API specification and endpoint documentation as the public contract.

## Public package boundary

The SDK repository exposes only the developer-facing client package. Lariba Cloud production applications, control-plane implementation, deployment infrastructure, security-sensitive systems, and proprietary automation remain private.

## Authentication and secret handling

Never embed Lariba Cloud API keys in browser-delivered source code, public environment variables, URLs, screenshots, event payloads, or source-control history.

Use credentials only in trusted server-side or controlled runtime environments and grant only the scopes required by the integration.
