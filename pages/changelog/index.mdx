# Changelog

This changelog records **public developer-documentation changes** and public integration-surface updates for Lariba Cloud.

Internal engineering milestones, production acceptance evidence, deployment details, recovery tooling, and private implementation history are intentionally excluded from this public repository.

## September 2026 — Public developer-surface alignment

### Changed

- Clarified the boundary between public developer interfaces and private Lariba Cloud implementation.
- Removed internal backend-development environment material from the public documentation site.
- Reduced operational recovery documentation to developer-visible behavior and supported expectations.
- Updated the Quickstart to use the canonical public HTTP ingestion contract.
- Updated JavaScript/TypeScript SDK guidance to reflect its current package metadata and developer-preview compatibility boundary.
- Updated repository links to the NODE63 Labs GitHub organization.
- Added an explicit MIT license for this documentation repository.

## Docs 0.4 — September 2026

### Added

- Source Creation guidance.
- Sentinel workflow guidance.
- Expanded public integration guidance for authentication, API keys, event ingestion, webhooks, concepts, and API references.

### Changed

- Public documentation emphasizes stable developer-facing contracts rather than internal implementation details.
- Secret-handling guidance consistently keeps credentials out of source control, browser-visible configuration, logs, and screenshots.
- SDK documentation separates package availability from production API compatibility.

## Docs 0.3 — July 2026

### Added

- Expanded Events API reference and event-ingestion guidance.
- Organization, project, API-key, usage, billing, webhook, error, and rate-limit documentation.
- Public operational guidance for retry-safe integrations, idempotency, and observable recovery behavior.

### Changed

- HTTP endpoint documentation became the authoritative production integration guidance where SDK compatibility was not yet established.
- API examples use environment-provided API origins rather than hard-coded production infrastructure details.
- Authentication guidance separates user-token flows from API-key authentication.

## Docs 0.2 — July 2026

### Added

- Delivery visibility and recovery-oriented public documentation.
- Retry, replay, and delivery-history guidance for authorized users.
- Capability-aware documentation for public operational controls.

## Docs 0.1 — June 2026

### Added

- Initial developer documentation foundation.
- Getting Started material.
- Core concepts.
- Event Sources.
- Event ingestion and Events API documentation.
- Authentication, idempotency, and error guidance.

## Release-note policy

Future public changelog entries should:

1. describe developer-visible behavior or contract changes;
2. distinguish documentation changes from API or SDK compatibility changes;
3. avoid publishing credentials, customer data, private infrastructure details, internal recovery procedures, or security-sensitive implementation;
4. link only to stable public developer resources;
5. avoid presenting internal engineering evidence as part of the public product contract.
